## Findings that change how the tables read

- **The pitch-profile seed is erased before any audio is processed.** `loadProfile()` seeds once at telemetry-thread start (EM:183). `NotchBank::prepare()` zeroes the histogram (NB:109) on every `audioDeviceAboutToStart` (AE:208). JUCE calls that from `addAudioCallback` (`engine/build/_deps/juce-src/modules/juce_audio_devices/audio_io/juce_AudioDeviceManager.cpp:1054-1055`), which the engine reaches at EM:369 on every reconfigure. Channels are 0 until that reconfigure (AE:500, EM:370). This is by call order, not by running it.
- **Hold time has a third source.** `holdSeconds` runs at 10.0 s from the atomic initialiser `releaseSeconds { 10.0f }` (AE:519, applied AE:286). That is neither `EngineDefaults.h` nor the bank's member default of 2.0 (NB:919). LD and TF never set it and run 2.0.
- **The chirp probe is dead.** Nothing ever stores 1 into `probeState` (evidence in the last section).
- **Plateau path, comb, harm budget and pulsing are all off by value** and unreachable in the shipping engine.
- **`qMaxHigh` and `qWidenAboveHz` are read only by `qMaxAt()`, which has no caller.**
- **`[dbg]` printing is unconditional** at about 5 Hz (EM:475).

The specific questions:

- **Pulsing at `dutyCycle` 1.0:** not reachable. Line 714 returns before `pulseHz`, `pulseEdgeMs` or `pulsePhase` are read.
- **Comb:** `openComb` is called only at NB:463, for a new filter, when `wide && widthHz > 0.25·f`. `wide` comes only from path-4 events, so it is never applied in the shipping engine.
- **`fastTrackCutDb`:** fed by offender memory only. `noteOffender` adds 1 per new filter (482, 529) and `seedOffender` adds the profile (1125); the count decays with a 300 s half-life in one exact 1/24-octave bucket (1086-1105).
  - Depth memory clamps the result to `hardCapDb` only when `rememberedDepth < 0` (434-436). Otherwise -24 stands, 6 dB past the dial.
  - The test is `>= 3` on a continuously decaying count (1094-1099), so three unit strikes at distinct times sum to less than 3.
- **Depth memory:** written only on re-trigger (`noteDepth`, 361) and read over ±3 buckets (1171-1186). At shipping values its effects are the clamp above and `primedCapHits = 2` when the remembered depth is ≤ -17.75 (442), which any re-triggered filter satisfies because filters open at -18.
- **`loopVerdict`, `futileHitsBeforeGivingUp`, `futileCutDb`:** every trigger on an existing filter counts as futile if total cut ≤ -20 and the level rose > 1 dB (157-165). At 6 the slot is marked ineffective and the conclusion is latched for display (167-180).
  - While any slot is ineffective, every re-trigger in the bank is floored at `hardCapDb` and pulled back up to it (317-322, 348), and runaway depth is disabled (355, 447).
  - It clears on a release step (604) or when futileHits returns to 0 (163, 181).
